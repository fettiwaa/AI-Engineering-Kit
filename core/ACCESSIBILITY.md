# Accessibility

## 1. Scope

Accessibility applies to all user-facing output of a project, including documentation, CLI
output, and UI components.

## 2. Principles

- Design inclusively from the start.
- Follow WCAG 2.1 AA as a baseline for UI work.
- Ensure keyboard navigation works without a mouse.
- Provide text alternatives for non-text content.

## 3. CLI

- Support screen readers via standard output.
- Avoid color-only status indicators.
- Document exit codes and output formats.

## 4. Testing

- Include accessibility checks where UI is in scope.
- Use automated linters as a baseline; supplement with manual review.

## 5. Documentation

- Use plain language.
- Provide alternatives for visual content.
- Keep a consistent, navigable structure.
